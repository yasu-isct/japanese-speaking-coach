# 对话中扫一眼就能用的界面

研究日期：2026-10-26。状态：已完成首轮推荐层级与中文折叠的合成输入截图对照，见 [首轮记录](reports/ui-iteration-20261026.md)；其余原则仍是设计目标，真人效果尚未验证。

目标场景是视频通话和线上日语课。使用者主要在听人说话、看对方或课件，字幕窗只承担两个即时任务：看懂刚才的话，找到现在可以念的一句。学习解释和回看应随手可得，不必一直占据主视线。

## 官方工具给出的参考

以下是官方说明中的实际功能；最后一列是本项目据此作出的设计判断，不是这些工具已替本项目验证过的结论。

| 来源 | 已核对的做法 | 在本项目中的取舍 |
|---|---|---|
| [YouTube 字幕设置](https://support.google.com/youtube/answer/100078?hl=en) | 字体、字号、文字与背景透明度可调；选项会保留到再次修改或重置 | 字幕要能适应观看距离和视频背景；后续保存字号、位置和显示选择，提供恢复默认 |
| [Microsoft Teams 实时字幕](https://support.microsoft.com/en-us/teams/meetings/use-live-captions-in-microsoft-teams-meetings) | 字号、颜色、显示行数、字幕位置可调 | 字幕面积和位置应受控；更多历史放在历史窗，避免主窗随对话一直长高 |
| [Microsoft Immersive Reader](https://support.microsoft.com/en-us/accessibility/word/use-immersive-reader-in-word) | 行聚焦可突出一、三或五行；可调整文字与背景；词典和翻译按需使用 | 当前日语与推荐回复优先；中文解释、推荐理由和查词作为按需展开的学习信息 |

借用 WCAG 的可测量原则作为桌面界面的内部检查线，不声称 tkinter Canvas 已满足完整的无障碍标准：普通文字与背景对比度至少 4.5:1；颜色不能是唯一的信息线索。[对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[颜色使用说明](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)。控件应容易点到，状态提示应可见而不抢走操作焦点。[目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)、[状态消息说明](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)。

## 现有界面的起点

依据 [overlay.py](../app/jsc_live/overlay.py)、[history.py](../app/jsc_live/history.py)、[main.py](../app/jsc_live/main.py) 的代码检查；以下不是截图测量结果。

| 现状 | 应保留或验证的地方 |
|---|---|
| 三条回复按丁寧／カジュアル／かんたん固定排列；推荐正文较亮，标签带黄色 ⭐ | 保留固定位置，在此基础上增加文字和字重层级；避免每轮换位置，让眼睛重新寻找 |
| 字幕默认 16 pt；建议约 13 pt；中文约 9 pt；可滚轮调字号 | 推荐句是需要念出口的内容，不应靠缩小它节省空间；先检查最小字号下的日语、假名和警告 |
| 中文意思、⚠ 警告合在一行，理由常显；中文行没有设置换行宽度 | 折叠中文前先把警告独立出来；长中文要换行，不能伸出窗口 |
| 新请求的 pending 替换整块旧建议；每次流式更新重新计算窗口高度，底边固定 | 有先缩小、后逐行长高的风险；是否造成可见闪烁或追读困难，需用相同事件序列截图／录屏验证 |
| 默认保留最近五句字幕；历史窗默认显示、占屏幕高度约 60% | 主窗和历史窗合计遮挡需测量；用户往上翻历史时不强制滚到底，这一点保留 |
| 收起、字幕、完整、历史、关闭可直接点击；滚轮功能没有可见提示 | 保留一步操作；给字号和透明度操作一个可找到的简短说明 |
| 加载、等待、超时提示混用中日文；部分错误直接带程序异常文字 | 状态统一用简短中文，说明现在发生了什么、下一步能做什么；详细异常留在日志 |

当前颜色以不透明背景计算时对比度较高，但透明度会改变结果。用代码中的色值做 sRGB 合成计算，在纯黑／纯白底图中取较低值：默认透明度 0.88 时，推荐正文约 12.25:1、次要正文约 5.84:1、中文约 5.70:1；透明度 0.30 时分别约 1.93:1、1.54:1、1.53:1。这只是纯色字心的分析计算，未包含字体抗锯齿和真实视频背景，不能代替渲染检查。后续应保留一键恢复清晰背景的入口，不能通过把非推荐回复变得难以看清来制造层级。

## 原则与验收方法

数值中除已引用的对比度原则外，其余均是本项目初始设计目标，后续按实测调整。每次记录改前、改后和未通过项，不凭“看起来更好”下结论。

| 检查项 | 原则 | 可核对的验收方法 |
|---|---|---|
| 可读性 | 日语正文能完整读完，假名不碰字、不被截断；【待填写】不能被省略到看不见 | 固定短句、长句、长注音词、占位符和长中文各一例；在 1366×768、1920×1080 及 Windows 100%／150% 缩放下检查内容边界与换行；记录无法验证的设备条件 |
| 信息层级 | 推荐句最容易找到；保留另两条可比较的回复；警告不依赖颜色 | 同一建议恰好一处「⭐ 推荐」标识；推荐字重或背景区别在灰度查看时仍成立；中文折叠后 ⚠ 仍可见；真人后续检查“能否两秒内指出推荐句”，未测前不宣称达成 |
| 遮挡 | 最近字幕与本轮建议有面积上限，回看去历史窗 | 固定字体与输入，记录主窗宽高、占屏幕面积比例、历史窗开／关；1366×768 下先以主窗不超过工作区高度 45% 为设计目标；超出时先收起学习解释，不自动缩小日语；任意模式保持关闭入口在屏幕内 |
| 对比度 | 主次文字都要看得清；推荐、警告同时有符号或文字 | 对实际使用的正文、假名、中文、按钮文字测前景／背景对比；普通文字目标 ≥4.5:1；叠在黑、白、复杂测试背景上分别检查默认透明度；低透明度结果另列，不能用默认值冒充全范围通过 |
| 字号 | 使用者能轻松放大；推荐句不小于其它建议正文 | 记录字幕、推荐、其它回复、假名、说明的实际 pt 与渲染像素；默认推荐至少与其它日语建议等大；分别检查默认、最小档、放大到两倍时的裁切和功能入口。两倍是本项目目标，WCAG 的文字缩放条款本身对字幕有例外，不能误称字幕的强制合规要求。[文字缩放说明](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) |
| 操作步数 | 高频操作在窗口上就能发现，不要求背命令 | 中文展开／收起、历史显示／隐藏、字幕／完整／收起均一步；移动一拖即可；记录从初始画面到操作完成的点击数。按钮目标先按至少 24×24 个 100% 缩放逻辑像素设计，再实测高 DPI，不能把 CSS 像素与 Tk 像素直接等同 |
| 稳定与提示 | 阅读期间少移动内容；请求状态清楚；不抢焦点、不弹重复对话框 | 固定事件序列含逐行返回、超时后成功、网络失败、新请求覆盖旧请求；统计空白清屏次数与窗口尺寸变化次数，目标新请求不先缩成一行；只展示最新一轮，旧回复若保留必须标“上一轮”；静音不直接判定为设备故障 |

## 最小迭代顺序

**第一步：让推荐容易找到，把解释变成可选。** 保留三种风格顺序，在当前推荐的标签中写「⭐ 推荐」，适度增加字重；加入一个明确的「收起中文／展开中文」入口，同时控制中文意思与理由。首次沿用当前“显示中文”的行为，使用者能主动收起；记住选择放到后续一步。警告独立呈现在对应日语旁，无论中文是否展开都保留。只改变显示，不重新调用建议接口；先做改前截图，再实施和做改后截图。

**第二步：减少等待期间的跳动。** 在同一轮流式返回中保留稳定的三条位置；新请求不能先把建议区缩成一个省略号。可以保留上一轮到新回复就绪，但必须明确写“上一轮／正在准备新回复”，避免把旧话当成当前答案。用固定事件回放比较空白次数、尺寸变化和首条可读回复出现时间；不得以延后显示整段结果换取稳定感。最终建议仍须满足现有 p95 ≤3 秒约束。

**第三步：让状态和操作说人话。** 状态示例为“正在准备识别”“正在听系统声音”“正在准备回复”“回复暂时没连上，请检查网络”。只有实际检测支持时才显示“暂时没检测到声音”；提示检查播放设备，不把停顿当成报错。增加可见的操作说明，之后再做字号／位置／模式保存和更完整的键盘操作。外部资料功能接入时，应在其入口写清楚“查到的片段会发给 API”，不要在每句回复中重复打断。

以上三步分开验证和记录；浅色主题、位置预设、首次引导、键盘可访问性作为后续候选，不与第一步一起扩张。

## 每轮留下什么证据

使用相同的公开测试句或合成输入、相同窗口位置、屏幕分辨率、缩放、字体、透明度和应用版本。改前截图、改后截图、事件回放记录及六项主检查结果放进 `logs/ui-iterations/<日期>-<主题>/`。用于公开展示的副本只可包含虚构或 TTS 内容，并标明“合成输入”，放入 `docs/images/`。

记录至少包括：推荐与警告能否辨认、截断／重叠数量、窗口宽高及遮挡比例、对比度计算条件、各文字实际字号、每项操作步数；涉及等待显示时再记录清屏次数、尺寸变化次数、首条可读回复时间和最终显示延迟。截图能证明布局，不能证明人在真实课堂中更省力；这部分明确记为待真人验证。
