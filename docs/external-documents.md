# 外部文档读取（D-032 / D-033）

在“资料”里选择文件夹，放入 `.docx` 或文字PDF，再点“重新读取资料”。Word正文、简单表格和PDF文字会进入现有关键词/本地多语言检索；只有选出的相关片段随问题发给生成API。文件本身、图片、附件和未选中的正文不会整体上传。原文件不改写，也不会启动Word或PDF查看器。

## 当前能读什么

| 格式 | 内容与出处 | 限制 |
|---|---|---|
| UTF-8 md/txt | 原有段落、标题和原文件行号 | 单文件64KB |
| docx | 正文段落与非合并、非嵌套的简单表格；出处如`course.docx:第2段`、`course.docx:表1・第2行` | 单文件10MB；解压后主正文XML≤4MB；仅读取`word/document.xml` |
| 文字PDF | 按物理页提取，出处如`course.pdf:第2页`；不跨页合并 | 单文件10MB、最多80页，单次处理15秒上限；无OCR、拒绝加密文件 |

DOCX的“段”是正文非表格段落的顺序，包含标题和空段，跳过整段删除内容；表格按正文中出现的顺序编号。它不是Word页面或屏幕行号，分页变化不会被伪装成固定页号。表格只有明确标记为表头的首行才作为后续行的列名背景。标题识别内置Heading1～6及常见中文标题样式名，未解释整个自定义样式系统。

Word不解析图片、扫描件、文本框、页眉页脚、脚注、批注、附件、外部关系和自动编号样式。直接标记为隐藏或删除的文字、域代码、注音读音会跳过，保留普通可见文本/插入修订/超链接显示文字/注音正文。这里是正文提取器，不是完整Word渲染器；隐藏样式继承、复杂表格和自定义布局尚未支持。合并/嵌套表格明确跳过并给读取提示，不能认为整份复杂文件已完整导入。旧`.doc`和扫描件请先转为docx或纯文字，OCR尚未接入。

D-034默认容量为128文件、40万正文字、2048片段；单份Word/PDF仍限10万字，每次回答仍最多4片段/1800正文字。窗口刷新显示进度、可以取消，末文件截断会明确提示。前后对照与约24秒的较大库建索引耗时见[容量记录](materials-capacity-20261026.md)。目录刷新在后台建立新快照，正在生成和已显示的回答继续保留原片段、原目录和原出处。坏DOCX/PDF不会阻塞旁边的有效文件；读取失败和特殊结构提示在资料窗口的滚动区域显示，不作为参考资料发给API。

## Word实现与D-032证据

使用Python标准库ZIP/XML，不增加依赖、不解压到磁盘、不访问文档链接。解析前限制压缩文件、ZIP条目和解压XML大小；拒绝DTD，限制XML深度/节点及提取字数。DOCX正文由段落与表格构成，分别映射到稳定的正文位置；结构参考[Microsoft WordprocessingML文档](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-open-and-add-text-to-a-word-processing-document)及[表格说明](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-change-text-in-a-table-in-a-word-processing-document)。没有引入Office自动化或新界面框架。

固定两份虚构Word、十问：改前读取1份说明txt，Word都忽略，目标片段0/10；改后读取3文件、17片段，关键词9/10，本地多语言10/10。多语言启动含模型/索引单次1357.37ms，十问检索及序列化p50/p95为3.59/5.04ms（nearest rank；十问p95为最大值）；并非API或可见延迟。旧47份资料载荷保持逐字一致。全部262项检查，261通过、1项Windows符号链接权限跳过。

基线及结果：`tests/live_suggest/docx-materials-{before,keywords,semantic}-20261026-*.json`；旧资料一致性：`model-preferences-20261026-213633.json`；截图/哈希汇总：`docx-stage-20261026.json`。0生成API、无私人资料或真实设置改动。没有重新微调个人资料真实性，也没有把检索覆盖写成回答正确率。更多办公软件导出的真实布局、较大资料库与真人课堂仍待后续。

可复现性补检：最初Windows运行的说明txt/问题JSON使用CRLF，提交样本统一为LF，两个Word字节未变。已另跑离线本机检索，10份资料载荷逐字保持、10个预期段落/表格位置全部匹配；原始证据的原哈希保留，LF版本记录为`docx-materials-verified-20261026-214440.json`。


## PDF读取与D-033证据

文字PDF按文件内实际页面顺序从1编号；页上印的页码、罗马数字或封面编号可能不同。图片/扫描页不做OCR，空页也不伪造文字；混合PDF中保留有文字的页并提示哪些页没有提取到。页眉页脚可能进入文字，复杂表格、双栏顺序和特殊字体不能保证还原。密码文件不尝试解密，也不索要密码。

解析使用[pypdf 6.21.2（官方PyPI，BSD-3-Clause）](https://pypi.org/project/pypdf/6.21.2/)，纯Python wheel约407.8KB，已固定在app/requirements.txt和requirements-dev.txt。只安装基础包，没有增加OCR、GPU模型或界面框架。pypdf支持提取已有文字，扫描图片需要另行OCR；复杂内容流可能占用较多内存，因此采用文件/解压流/页数等限制，并在隐藏子进程中设置15秒超时。[官方提取说明](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)

父进程通过stdin传入已读取的字节，不向子进程传资料路径；Windows使用CREATE_NO_WINDOW，不启动外部查看器。每页内容流最多2MB，累计8MB，库的解压/解析/页面树/XObject调用也收紧限额。超时结束子进程并返回可操作提示，失败文件不发布部分片段。解析只发生在建立/刷新索引时，提问时从内存查找。组件缺失时仍可读取其它格式，界面提示更新应用依赖。

两份虚构文字PDF共4页，另有1页纯图片PDF。先冻结十问：未支持时0/10；接入后关键词8/10、本地多语言9/10，所取目标页码与原页一致。询问午餐的日语问题仍漏掉中文资料，保留失败不改题。277项测试，276通过、1项Windows权限跳过；原md/txt的47份与Word的10份载荷全部不变。无新增生成API，不代表回答正确率或可见延迟。

单次三文件解析+关键词索引998.12ms；含加载模型和语义索引2228.37ms；十问语义检索/序列化p50/p95为3.52/4.22ms，十样本nearest-rank p95即最大值。另一次实际隐藏子进程索引995.63ms、前台HWND不变。不同阶段有并行测试，不能拿单次时间差声称优化。全部5页已用Poppler绘成图检查，字体替换提示存在，但字形可读；这里只证明小型合成文档。UI截图、自评和证据见`docs/ui-pdf-materials-20261026.md`、`tests/live_suggest/pdf-stage-20261026.json`。下一步检查更大资料库、长PDF的主题切分与跨语言漏查，保留复杂版面/OCR及真人验收缺口。
