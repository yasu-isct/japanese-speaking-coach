# 外部文档读取（D-032）

在“资料”里选择文件夹，放入 `.docx`，再点“重新读取资料”。Word正文和简单表格会进入现有关键词/本地多语言检索；只有选出的相关片段随问题发给生成API。文件本身、图片、附件和未选中的正文不会整体上传。原文件不改写，也不会启动Word。

## 当前能读什么

| 格式 | 内容与出处 | 限制 |
|---|---|---|
| UTF-8 md/txt | 原有段落、标题和原文件行号 | 单文件64KB |
| docx | 正文段落与非合并、非嵌套的简单表格；出处如`course.docx:第2段`、`course.docx:表1・第2行` | 单文件10MB；解压后主正文XML≤4MB；仅读取`word/document.xml` |

DOCX的“段”是正文非表格段落的顺序，包含标题和空段，跳过整段删除内容；表格按正文中出现的顺序编号。它不是Word页面或屏幕行号，分页变化不会被伪装成固定页号。表格只有明确标记为表头的首行才作为后续行的列名背景。标题识别内置Heading1～6及常见中文标题样式名，未解释整个自定义样式系统。

不解析图片、扫描件、文本框、页眉页脚、脚注、批注、附件、外部关系和自动编号样式。直接标记为隐藏或删除的文字、域代码、注音读音会跳过，保留普通可见文本/插入修订/超链接显示文字/注音正文。这里是正文提取器，不是完整Word渲染器；隐藏样式继承、复杂表格和自定义布局尚未支持。合并/嵌套表格明确跳过并给读取提示，不能认为整份复杂文件已完整导入。旧`.doc`和PDF当前请另存为docx或纯文字，OCR尚未接入。

整体仍沿用64文件、10万正文字、256片段和每次最多4片段/1800正文字的上限。目录刷新在后台建立新快照，正在生成和已显示的回答继续保留原片段、原目录和原出处。坏DOCX不会阻塞旁边的有效文件；读取失败和特殊结构提示在资料窗口的滚动区域显示，不作为参考资料发给API。

## 实现选择与证据

使用Python标准库ZIP/XML，不增加依赖、不解压到磁盘、不访问文档链接。解析前限制压缩文件、ZIP条目和解压XML大小；拒绝DTD，限制XML深度/节点及提取字数。DOCX正文由段落与表格构成，分别映射到稳定的正文位置；结构参考[Microsoft WordprocessingML文档](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-open-and-add-text-to-a-word-processing-document)及[表格说明](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-change-text-in-a-table-in-a-word-processing-document)。没有引入Office自动化或新界面框架。

固定两份虚构Word、十问：改前读取1份说明txt，Word都忽略，目标片段0/10；改后读取3文件、17片段，关键词9/10，本地多语言10/10。多语言启动含模型/索引单次1357.37ms，十问检索及序列化p50/p95为3.59/5.04ms（nearest rank；十问p95为最大值）；并非API或可见延迟。旧47份资料载荷保持逐字一致。全部262项检查，261通过、1项Windows符号链接权限跳过。

基线及结果：`tests/live_suggest/docx-materials-{before,keywords,semantic}-20261026-*.json`；旧资料一致性：`model-preferences-20261026-213633.json`；截图/哈希汇总：`docx-stage-20261026.json`。0生成API、无私人资料或真实设置改动。没有重新微调个人资料真实性，也没有把检索覆盖写成回答正确率。PDF、更多办公软件导出的真实布局、较大资料库与真人课堂仍待后续。

可复现性补检：最初Windows运行的说明txt/问题JSON使用CRLF，提交样本统一为LF，两个Word字节未变。已另跑离线本机检索，10份资料载荷逐字保持、10个预期段落/表格位置全部匹配；原始证据的原哈希保留，LF版本记录为`docx-materials-verified-20261026-214440.json`。
