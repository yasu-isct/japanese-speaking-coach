# 项目设计：日语口语助手（japanese-speaking-coach）

> 本文描述第一阶段（Skill）的实际设计。每个设计点「为什么这样做」的完整推理在 `decisions.md`（D-001 起）。
> 第二、三阶段只记录方向，尚未设计。

## 1. 要解决的问题

在日本生活、学习、工作的中文母语者（约 N4–N2）在真实对话里有三个卡点：

| 卡点 | 典型场景 | 本项目的对策 |
|---|---|---|
| 听不懂 | 店员的服务敬语、同事的口语缩约、言外之意（「ちょっと…」） | 带假名的原文 + 一句中文意思 + 1 条关键要点 |
| 接不上 | 知道意思但说不出，或不知道该用哪种礼貌程度 | 3 种回复建议 + 推荐 1 条（⭐） |
| 记不住 | 练过的说法下次又忘 | 复盘纠错 + 导出 Anki 生词卡 |

使用时的关键约束：**用户往往正在对话中，只有几秒钟看屏幕。** 所以输出必须「先给能说出口的，解释放后面」。

## 2. 分阶段路线

| 阶段 | 形态 | 内容 | 状态 |
|---|---|---|---|
| 一 | Claude Skill | 回复建议、表达转换、情景陪练、复盘 + Anki 导出 | 本文 |
| 二 | 桌面/移动应用 | 实时日语字幕（语音识别 + 假名），复用第一阶段的输出格式 | 未开始 |
| 三 | — | 由第二阶段的使用情况决定 | 未开始 |

第一阶段先用 Skill 验证「输出格式和教学策略」是否有用，再投入工程量做实时字幕。Skill 的输出格式被刻意设计成可解析的（D-002），第二阶段可以直接复用。

## 3. 第一阶段架构

```
skill/
├── SKILL.md                  # 入口：角色、模式判断、四种模式的输出格式与规则
├── references/
│   ├── politeness.md         # 敬语判断规则（⭐ 推荐流程、标记清单、常见失礼）
│   └── scenarios.md          # 8 个情景卡片（陪练用）
└── scripts/
    └── export_anki.py        # 复盘生词卡 → Anki 导入文件（纯标准库）
```

- **渐进式加载**：SKILL.md 只放每次都需要的规则；敬语细则和情景库放在 `references/`，只在需要时读取，控制主提示词长度（D-003、D-007）。
- **脚本只用标准库**：Claude 的代码执行环境不能安装依赖，所以 `export_anki.py` 不引入任何第三方包。

## 4. 四种模式

| 模式 | 触发 | 输出 |
|---|---|---|
| A. 回复建议（默认） | 粘贴一句日语 | 听懂 → 回复建议（丁寧/カジュアル/かんたん，⭐ 一条）→ 生词 |
| B. 表达转换 | 「我想说……」「……用日语怎么说」 | 你想说 → 回复建议 → 生词 |
| C. 情景陪练 | 「陪练」「练习 + 场景」 | AI 扮演对方，每轮一次发言；必要时 💡；卡住时给 A 模式帮助 |
| D. 复盘 | 「复盘」 | 纠错表 → 做得好的地方 → 生词卡（CSV） |

### 4.1 A 模式的输出格式（核心）

```
## 听懂
原文：週末(しゅうまつ)何(なに)してたんですか？
意思：你周末做什么了？
要点：「してた」是「していた」的口语缩约。

## 回复建议
1. 丁寧⭐｜【友達(ともだち)と鎌倉(かまくら)】に行(い)ってきました。〇〇さんは？
   → 和朋友去了镰仓。你呢？
2. カジュアル｜【友達(ともだち)と鎌倉(かまくら)】行(い)ってきた！〇〇は？
   → 和朋友去镰仓了！你呢？
3. かんたん｜【家(いえ)でゆっくり】しました。
   → 在家好好休息了。
推荐理由：对方用了です/ます，按同等礼貌程度回答最稳妥。

## 生词
- ゆっくりする：悠闲地度过、好好休息
```

设计要点（详见 D-002、D-004、D-006）：
- **信息按紧急程度排序**：能说出口的回复在前，解释在后。
- **恰好一个 ⭐**：替用户做「用哪种礼貌程度」的决定；判断流程见 `politeness.md`（D-003）。
- **かんたん 是保底回答**：最多 2 个短句、N4 以内，紧张时也说得出口。
- **【】标出个人事实**：模型不编造用户的经历。
- **全部注音 `漢字(かな)`**：在任何界面都能显示，且能无损转换成 Anki 的 `漢字[かな]`。
- **⚠ 对此对象不要用**：对上司/老师/客户/面试官/店员时，カジュアル 照样给出但加警告，写在中文行而不是日语行。

### 4.2 推荐（⭐）判断流程

1. 用户要最简单的说法 / 表示紧张 → かんたん
2. 用户说明了对象 → 查对象表（上下关系不对称：上司说普通体，你仍用丁寧）
3. 对方用了丁寧语标记 → 丁寧
4. 对方用普通体**且**有口语标记 → カジュアル
5. 判断不了 → 丁寧（太礼貌的代价远小于失礼）

### 4.3 情景陪练

8 张情景卡片（N4×2、N3×4、N2×2），每张包含：开场白（固定）、流程节点、变化（随机选一）、完成条件、听力难点、常见失礼。
「节点 + 变化」而不是完整台词：既能自然回应学生，又不会跑题，并且有可判定的终点（D-007）。

### 4.4 复盘与 Anki 导出

复盘末尾输出固定列名的 CSV 块（`front,reading,meaning,example`），`export_anki.py` 提取所有 CSV 块、去重，生成 Anki 2.1.55+ 可直接导入的 TSV（带 `#separator` / `#notetype` 等文件头），例句中的 `漢字(かな)` 转成 Anki 的 furigana 语法。

## 5. 质量保证

| 层次 | 方法 | 文件 |
|---|---|---|
| 格式 | 20 句测试集 + 自动格式检查（标题、⭐、句数、注音、原文逐字等） | `tests/sample_dialogues.md`、`tests/check_format.py` |
| 日语正确性 | 另一个更强的模型盲审（语法/角色/立场/语体/读音为硬性），人工抽查校准 | `tests/review_prompt.md`（D-005） |
| 情景陪练 | 两个独立代理：教练（Skill）× 学生（N3 人设，预埋错误），主会话逐字转发 | `tests/roleplay_*.md` |
| 脚本 | 标准库 unittest | `tests/test_*.py` |

迭代原则（D-004）：失败时先区分「模型没遵守规则」还是「规则本身不合理/有歧义」，前者加强规则或示例，后者改规则；示例避开测试集原句，防止测试高估效果。

## 6. 已知局限

- 测试中的「用户」和「学生」都是模型扮演，真实学习者的输入会更乱（语音识别错字、中日混杂）。
- 日语审查员也是模型，可能与生成模型有共同盲点；最终依据是母语者人工抽查。
- 推荐规则只看语言标记和用户说明的对象，无法感知现场氛围（例如关系很好的上司）。
